# diagnosing-bugs: 構造化デバッグ

推測で修正を当てにいかない。**観測してから直す**。以下の順で進め、各段の結論を一言で残してから次へ進む。

## 手順

1. **再現(Reproduce)** — まず確実に落ちる/再現する最小の実行手順を1つ固定する。再現できない不具合は直せない。環境依存(fish 対 sh、TCC、権限)を疑い、どの条件で出てどの条件で出ないかを分ける。
2. **最小化(Minimize)** — 再現する範囲を削れるだけ削る。関係ない入力・ステップ・ファイルを外し、「これ以上削ると再現しなくなる」核まで縮める。切り分けが仮説の解像度を決める。
3. **仮説(Hypothesize)** — 何が起きていると考えるかを**具体的に1つ**言語化する。「たぶん環境変数」ではなく「PATH に ~/.local/bin が無く mlx_whisper が解決できていない」まで落とす。
4. **計測(Instrument)** — 仮説を**観測点で検証**する。print/echo/ログ、`set -x`、終了コード確認、`stat`/`ls -la`(シンボリック確認)、`ollama ps`ではなく実推論での生存確認、など。想像で埋めず、実際の値を見る。
5. **修正(Fix)** — 観測で確定した原因**だけ**を直す。ついでの改変を混ぜない(切り分けが濁る)。
6. **回帰確認(Verify)** — 手順1の再現ケースが直り、かつ隣接ケースを壊していないことを確認する。直った理由を一言で説明できるまで詰める。

## この環境の落とし穴(実例)

- **fish 関数は Bash(sh)から呼べない → exit 127**。`ask-*` 等は CLI を直接叩き、`cd /tmp &&` から。
- **Vault を触る launchd は TCC で全滅**する。自動化は SessionStart フックパターンで実装されている前提で疑う。
- **Ollama のメタAPI(list/ps)が応答しても推論が生きているとは限らない**。ハング時は `brew services restart ollama`。生存確認は embed/generate を実際に投げる。
- **~/.claude 配下(skills/scripts/commands/agents)は dotfiles へのシンボリック**。編集反映やファイル所在の齟齬はまず inode(`stat -f '%i %N'`)で同一物か確認。
- **フックが発火しない**ときは matcher・実行権限(`chmod +x`)・パス・settings.json の JSON 妥当性を順に計測する。

## 原則

- 一度に1つの仮説だけ検証する。同時に複数いじると原因が分からなくなる。
- 「たぶん直った」で終わらせない。**なぜ直ったか**を説明できて初めて完了。
- 3回修正して空振りしたら、それは仮説でなく当て推量。手順2(最小化)に戻る。
