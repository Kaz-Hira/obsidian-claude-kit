# Vault のセマンティック検索

キーワード一致ではなく意味の近さで引く。**Vault の中を探すときの既定手段**であって、
ユーザーが `/vsearch` と打ったときだけのものではない。

## いつ自分から使うか

以下に当てはまったら、頼まれていなくても検索する。

- ユーザーが Vault 内の過去の記述を前提に話している(「前に書いたやつ」「あのノート」)
- 質問に答えるのに Vault の既存ノートを参照した方が確実なとき
- 新しいノートを書く前に、**同じ話題の既存ノートが無いかを確かめる**とき(重複の予防)
- ユーザーが挙げた固有名詞・概念が、この Vault でどう扱われているか知りたいとき

**Grep より先に使う。** Grep は表記が一致しないと当たらない。この Vault は日本語ノートが
大半で、同じ概念を「トークン節約」「文脈汚染」「cache read」と別の語で書いている。

## 手順

1. `$ARGUMENTS`(または文脈から立てたクエリ)が空なら、何を探したいか聞き返す。
2. まず索引を最新化してから検索する(増分なので変更がなければ一瞬):
   ```
   uv run --quiet {{CLAUDE_DIR}}/vault-search/vault_search.py index
   uv run --quiet {{CLAUDE_DIR}}/vault-search/vault_search.py search "<クエリ>" -k 8
   ```
3. 結果は `[距離] パス › 見出し` + 冒頭スニペットの形式。距離が小さいほど近い。
4. 上位ヒットのうち文脈が要りそうなものは Read で本文を確認してから答える。
   **単なるヒット一覧の転記で終わらせない。** どのノートに何があるかを一文で要約して返す。

## 自分から使ったときの作法

- 検索したこと自体を長々と報告しない。**結論(どのノートに何があったか)だけ**を答えに織り込む
- ヒットが的外れなら、それを根拠に「Vault には無さそう」と判断してよい。
  無いものを探して何度も引き直さない(言い換えての再検索は**1回まで**、その後は Grep へ)
- 読み取り専用。ノートは書き換えない

## 使わないとき

- **ファイル名・パスが既に分かっている** → そのまま Read する
- **機械的な文字列一致が要る**(特定の関数名、URL、タグの全件列挙)→ Grep
- **Vault の外**(dotfiles、コードベース)を探している → Grep / Explore

## 補足

- クエリは自然文でよい。ユーザーの質問文をほぼそのまま渡すのが基本
- 索引対象: Vault 全体から `.trash` / `.obsidian` / `template` / `attachments` と
  `ai: false` のノートを除いたもの。`Study/` や `daily/` も含まれる
  (AIコンテキストの「常時知識」規約とは別枠)
- 全再構築が必要になったら `index --full`
- 索引は PostToolUse フック(`vault-suggest-links-newfile.sh`)が新規ノート作成時に
  増分更新している。手順2の `index` はその取りこぼしを埋めるだけなので通常は一瞬
