Obsidian Vault の健全性を検査し、結果を解釈して報告する。

```
python3 {{CLAUDE_DIR}}/scripts/vault-lint.py
```

`--only critical` / `--only warn` / `--only suggest` で絞り込める。引数: **$ARGUMENTS**

## スクリプトが見ているもの

| 重大度 | 検査 |
|---|---|
| 重大 | リンク切れ・埋め込み切れ / auto-note-mover のタグ契約違反 |
| 警告 | `uniquenote.md` スキーマの欠落 / MOC の `ai:` 規約 / タグ表記ゆれ |
| 提案 | 孤立ノート / 内容の薄いノート / 未参照の添付 |

`daily/` はリンク切れの対象外。periodic-notes が `[[昨日]]` `[[明日]]` を機械的に張るため、未作成の日を指すのが正常な状態。

## 報告のしかた

生の出力をそのまま貼らない。件数を伝えたうえで、**手を打つ価値のあるものだけ**を挙げる。

検出は機械的なので、指摘が妥当かどうかは中身を読んで判断すること。特に次は誤検出になりうる。

- **リンク切れ** — Obsidian の記法を解説するノートでは、`[[ノートリンク]]` のような例示が本物のリンクとして数えられる。実体を確認する。
- **内容が薄い** — 意図的な短いメモかもしれない。
- **孤立ノート** — Inbox 的に使っている置き場なら問題ない。
- **未参照の添付** — 下書き用に置いているのかもしれない。

## 修正するとき

**勝手に直さない。** 何をどう直すかを提示し、承認を得てから編集する。

- 一括で機械的に直せるもの(タグ表記ゆれ、frontmatter の `title` 欠落)と、判断が要るもの(リンク切れの解決先、孤立ノートをどの MOC に繋ぐか)を分けて示す
- リンク切れは、リンクを消すのではなく**リンク先ノートを作る**ほうが妥当なことが多い。どちらが良いか訊く
- 孤立ノートは、`MOC/` 配下の適切なハブに `[[リンク]]` を1行足すのが定石

レポートのノートを Vault に書き出さない。指摘は会話の中で完結させる。
